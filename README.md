# SCOPE — 오토봇용 검측·분석 프로그램

강화학습 에이전트("오토봇")와 그 학습 환경을 **분해해서 정확히 재는** 프로그램입니다.

승률 하나만 보고 "잘 배웠다"고 판단하면 거의 항상 틀립니다. SCOPE는 그 판단이 성립하는지를
**구조로** 확인합니다 — 게임이 과제로 성립하는지, 그냥 쉬운 게임은 아닌지, 무엇을 보고 푸는지,
안에서 무엇이 바뀌었는지.

---

## 왜 만들었나

검사 도구가 41개까지 늘었는데 실제로 확인해보니 **33개는 아무도 부르지 않았고**, 서로 무엇이
겹치는지도 몰랐습니다. 그래서 결함을 심어 놓은 시험 게임 12종으로 재봤더니 —

> 기존 검사 3종이 심어둔 결함 10개 중 **3개만** 잡았습니다.

죽은 관측 칸, 값 범위 깨짐, 승패 미보고, 버튼이 결과를 안 바꾸는 게임 — 전부 통과시키고 있었습니다.
더 나쁜 것은 **승패를 안 알려주는 게임을 "어렵다"로 분류**하고 있었다는 점입니다. 결함이 난이도로
둔갑하면 사람은 엉뚱한 곳을 고칩니다.

SCOPE는 그 사고들을 **구조로 막습니다.**

| 겪은 사고 | SCOPE가 막는 방법 |
|---|---|
| 상수 기준선을 빼고 "전이 성립"이라 판정 → 뒤집힘 | `기준선` 명령이 **항상 상수를 같이 잰다** |
| 승률을 한쪽은 0~1, 한쪽은 0~100으로 재서 26건 허위 발화 | **단위 없는 지표는 기록 자체가 거부** |
| 시뮬레이션 값이 실측에 섞일 위험 | `measured / simulated / predicted` **필수 표기** |
| 같은 사안에 판정이 세 번 뒤집힘(원인은 조건 차이) | **조건 지문이 다르면 비교를 거부** |
| 검사마다 게임을 따로 굴림(비용 5배) | **한 번 굴려 여러 검사가 나눠 읽는다** |

## 빠른 시작

```bash
python scope.py 등록   <게임> [체크포인트]    # ★한 번에: 검사→기준선→능력→작업대
python scope.py 검사   <게임>                # 게임이 과제로 성립하는가
python scope.py 기준선 <게임>                # 무작위·상수로도 이겨지는 게임인가
python scope.py 능력   <게임> <체크포인트>    # 무엇을 보고 푸는가
python scope.py 해부   <체크포인트> [이전판]  # 안에서 무엇이 바뀌었나
python scope.py 조합   목록 | 부품 | 실행     # ★부품을 분해·조합해 실제로 굴려 비교
python scope.py 벤치   [게임…]               # ★어디가 병목인지 잰다
python scope.py 작업대 교정                  # 검측기 자신을 정답지로 대조
python scope.py 현황                         # 최근 실행들
```

실행 예:

```
$ python scope.py 검사 my_game
FAIL  판정 2건 | 무작위승률   0.0% 평균    2.0수 미종료 0 | 관측 5칸 버튼 5
      [NOWIN?] 제대로 끝난 판 180개가 전부 won=False — 어려운 것인지 못 재는 것인지 갈리지 않는다
      [EPLEN] 한 판이 평균 2.0수 — 첫 수부터 끝낼 수 있다는 뜻

$ python scope.py 기준선 my_game
  무작위           15.0%
  상수 버튼4       93.3%      ← 버튼 하나만 눌러도 이긴다
★이 게임의 기준선 = 무작위 15.0% · 상수 최고 93.3%(버튼4)
  어떤 정책이든 이 둘을 모두 넘어야 '배웠다' 고 말할 수 있다
```

## 특징

### 검측기도 정기 교정을 받습니다

실험실은 저울을 정기적으로 교정하고, **교정 기한이 지난 장비의 값은 쓰지 않습니다.**
SCOPE도 같습니다 — 결함을 일부러 심어둔 시험 게임으로 검측기 자신을 대조하고, 그 날짜를 기록합니다.
**14일이 지나면 그 검사의 결과를 판정에 쓰지 않습니다.**

```
$ python scope.py 작업대 교정
  OK  정상 게임          기대 [] → 나옴 []              ← 오탐 없음
  OK  죽은 칸 게임        기대 [DEADCELL] → 나옴 [DEADCELL]
  ...
교정 성공 — 검사들에 오늘 날짜를 찍었다
```

### 판정을 못 하면 "못 한다"고 말합니다

성능이 천장에 걸려 차이가 안 날 때, 그것을 "실패"로 적으면 거짓 기록이 됩니다.
SCOPE는 `통과 / 상수이하 / 무작위이하 / **판정불가**` 를 나눠서 냅니다.
신뢰구간이 겹치면 판정하지 않고 **표본을 늘리라고** 합니다.

### 추론하는 모델을 안에 두지 않습니다

SCOPE는 결정적 계산만 합니다. 같은 입력이면 같은 출력이 나옵니다.
"이 코어는 추론이 약해 보인다" 같은 서술을 만들지 않고, **숫자와 그 숫자의 조건**만 냅니다.
언어모델은 이런 프로그램에서 환각으로 오히려 방해가 됩니다.

## 게임을 붙이려면

파이썬 클래스 하나면 됩니다. 이름이 `Env` 로 끝나면 SCOPE가 찾습니다.

```python
class MyGameEnv:
    def __init__(self, seed=None): ...
    def reset(self) -> obs: ...
    def step(self, action) -> (obs, reward, done, info): ...
    n_act = 4          # 버튼 수
    obs_reserved = []  # (선택) 예약 칸 — 죽은 칸 검사에서 뺀다
```

`info` 에 `won`(이겼나)을 넣어야 승률을 잽니다. `score` 가 있으면 점수도 같이 잽니다.

★게임이 무엇인지 몰라도 검사가 돌아갑니다. 그래서 **전혀 다른 장르를 붙여도** 같은 검사가 걸립니다.

## 조합 — 무엇을 넣느냐보다 어떻게 잇느냐

같은 부품인데 **배치를 바꾸니 21.5%p 가 갈린** 실측이 있습니다(대체로 쓰면 −8.73%p,
보정으로 쓰면 +12.73%p). 그런데 조합을 손으로 하나씩 돌리면 수십 가지 × 몇 시간이라
사실상 못 해봅니다.

```
$ python scope.py 조합 실행 60 --판길이 900
  보상담당 | 심판결정 | 추론다리 |   판 | 출구까지 | 초당수
       켬 |      켬 |      끔 |   16 |   12칸 |  254
       켬 |      끔 |      끔 |   12 |   55칸 |  275
       끔 |      끔 |      끔 |   12 |  174칸 |  360
```

★**가짜 모델로 예측하지 않습니다.** 각 조합을 **짧게 진짜로 굴려** 잽니다.
그 값은 "어느 조합부터 길게 돌릴지 정렬하는 용도" 로만 쓰고, 판정은 정본 조건으로 다시 합니다.

## 병목은 고치기 전에 잰다

```
$ python scope.py 벤치
게임:resource_defense_env      267,606수/초    3.74us
신경망:화면12x120x160(cuda)      15,434수/초   64.79us
★병목 = 신경망:화면12x120x160(cuda) · 17.3배 차이
```

게임을 2.5배 빠르게 고쳤는데 전체가 하나도 안 변한 적이 있습니다 — 진짜 병목은 신경망이었습니다.
**어디가 병목인지부터** 재야 합니다.
