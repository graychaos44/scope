# SCOPE 설계 정본 (2026-08-13)

> 사용자 08-13: *"일단 스코프 완성부터 하고, 거기서부터 기존 것들 다 붙여서 진행해야지.
>  지금은 **스코프가 가장 우선**이야. **설계부터 다 하고, 설계가 끝나면 바로 만들자.**"*

이 문서가 SCOPE 의 **정본**이다. 흩어진 설계(뼈대·형식·API·배치기·폴더)를 여기로 모으고,
아직 만들 수 없을 만큼 성긴 자리를 채운다.

---

## 0. SCOPE 는 무엇인가

**오토봇을 분해해서 정확히 재는 프로그램.**

| | 오토봇 | **SCOPE** |
|---|---|---|
| 하는 일 | 게임을 한다 | 오토봇을 **잰다** |
| 안에 든 것 | 학습하는 신경망 | ★**추론하는 모델을 두지 않는다**(환각 금지) · 결정적 계산 + 시뮬 전용 모델 |
| 출력 | 승률 | **수치 + 그 수치의 조건 지문** |

★이름 근거: 오토봇은 검사받는 쪽, 스코프는 **보는 쪽**(사용자 결정, V708).

## 3. [5] 판정·통계 — 설계

**문제**: 지금은 평균만 본다. 08-12 하루에 소표본이 방향을 **세 번** 거꾸로 보여줬다.

| 넣을 것 | 왜 |
|---|---|
| **IQM + 층화 부트스트랩 신뢰구간** (rliable) | 규약이 이름까지 적어둔 표준. ★`venv_rliable` 에 **이미 설치돼 있다** |
| 시드별 값 항상 병기 | 평균만 보면 한 시드가 끌고 간 것을 못 본다 |
| **두 실행 비교** | 조건 지문이 다르면 **비교를 거부**한다(08-12 판정 3회 뒤집힘의 원인이 조건 차이였다) |
| 승격 규칙 | 도구 출력 = `CANDIDATE`. **팀장이 직접 확인한 것만** `CONFIRMED`(규약 §9-2) |

**판정 함수** (하나로 모은다):

```
판정(어댑터, 무작위, 상수최고, CI) →
  통과      : 어댑터가 무작위·상수 **둘 다** +5%p 초과, CI 겹치지 않음
  상수이하  : 상수최고 대비 +5%p 미만
  무작위이하: 무작위 대비 +5%p 미만
  판정불가  : CI 가 겹친다 → **표본을 늘려라**
```

★`판정불가` 를 실패와 **분리**한다 — 08-13 에 L5(parry)가 천장에 걸려 차이가 안 났는데,
  그것을 "실패" 로 적으면 거짓 기록이 된다(V701).

## 4. [6] 작업대 — 설계

**지금 있는 것**: `gate_run.py`(목록·배치·**교정 기한**) — SCOPE 로 흡수한다.

| 기능 | 내용 |
|---|---|
| 목록 | 검사할 대상(게임·어댑터·코어)과 이유·상태 |
| 한 번에 실행 | 대상 × 검사 종류를 배치로 |
| **교정 기한** | ★검측기를 정답지로 마지막에 대조한 날. **14일 넘으면 그 검사 결과를 판정에 안 쓴다** |
| 배치 | [8] 에이전트가 생기기 전에는 로컬·ssh 순차 |

★교정 기한이 SCOPE 의 특징이다 — 실험실이 저울을 정기 교정하고 **기한 지난 장비 값은 안 쓰는** 것과 같다.
  08-13 에 정본 검사 3종이 심은 결함 10개 중 3개만 잡는 것이 드러났는데, 그전까지 아무도 몰랐다.

## 6. [9] 코어 해부 — 설계

**읽기만 한다.** 고치지 않는다(사용자 08-13 명시).
목적은 두 가지고 **둘 다** 낸다:

### (가) 학습 건강 — "망가지고 있나"

| 지표 | 잡는 것 |
|---|---|
| `core.health.dead_unit_ratio` | 죽은 뉴런 |
| `core.health.act_mean/std` (층별) | 값 폭주·수축 |
| `core.health.weight_delta` (층별) | 증류·학습이 **어디를** 바꿨나 ← V655(가치헤드 소멸)를 즉시 잡았을 자리 |
| `core.health.norm_stats_changed` | 정규화 통계가 덮였나 ← 08-13 에 우연히 발견한 것 |

### (나) 능력 보유 — "뭘 할 줄 아나"

| 지표 | 어떻게 |
|---|---|
| `core.capability.<종목>_winrate` | 종목별 실측 |
| `core.capability.<능력>` | [4] 개입으로 잰 프로파일 |
| `core.repr_rank` | 표현 분해능 — 서로 다른 상황이 **같게 뭉개지나** ← V652 의 그 원인 |

### (다) 격차 = 다음 학습감

```
gap.<능력> = env.demand.<능력> − core.capability.<능력>
```

★★**함정**(V675): 내부 지표는 결과와 직결되지 않을 수 있다. 타깃망이 성능을 8.5%p 올렸는데
  내부 지표는 그걸 못 잡았다. → **결과와의 상관이 확인된 것만 판정에 쓴다.**
  확인 전에는 **표시만** 한다(합격·불합격을 매기지 않는다).

## 9. 완성 판정 (SCOPE 가 다 됐다고 말할 수 있는 조건)

| # | 조건 |
|---|---|
| S1 | 게임 하나를 등록하면 **사람 손 없이** 검사→기준선→능력→격차가 다 나온다 |
| S2 | 모든 결과가 **조건 지문과 함께** 실행 대장에 쌓인다 |
| S3 | 정답지(gcorp) 12종에서 **오탐 0 · 심은 결함 전건 검출** |
| S4 | 교정 기한이 지난 검사의 결과는 **판정에 안 쓰인다**(도구가 막는다) |
| S5 | 시뮬값과 실측값이 **한 번도 섞이지 않는다** |
| S6 | 옛 도구가 내던 값과 **같은 값**을 낸다(회귀 대조) |
