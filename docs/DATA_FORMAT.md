# 기록 형식·인코딩 규격 (2026-08-13)

> 사용자 08-13: *"우리 내부 기초 데이터 생성은 이렇게 하고 로그도 이런 식으로 하고,
>  나중에 다른 파일로 변환하는 기능만 넣어 두면 될 것 같은데. json 이나 md 같은 걸로 아웃풋 가능하면 괜찮을 것 같아.
>  그리고 **언어가 깨지지 않게 유니코드나 이런 거 잘 정해야 할 것 같은데?**
>  원본 이진이 있으면 그걸로 나중에 다시 복구되긴 하겠지만 시간 아깝잖아."*

★맞다. 인코딩은 **터진 뒤에 고치면 제일 귀찮은 자리**다. 지금 못박는다.

---

## 1. 지금 상태 (실측 2026-08-13)

| 항목 | 현황 | 판정 |
|---|---|---|
| 본문 인코딩 | UTF-8 · 줄바꿈 LF | **정상** |
| JSON 저장 시 한글 | **480곳이 `ensure_ascii` 미지정** → `한글` 로 저장 | ★고쳐야 |
| 파일 열기 | **175곳이 `encoding=` 미지정** → 기기 로케일에 의존 | ★고쳐야 |
| 로그 파일명 | 한글 이름 **62개**(`jobs/T계열_*.log`) | ★고쳐야 |
| 시각 표기 | ISO 8601 쓰는 곳/안 쓰는 곳 혼재, **타임존 없음** | ★정해야 |

★한글이 `\uXXXX` 로 저장돼도 읽으면 복구된다. 그러나 **사람이 `head` 로 못 읽는다** —
  원본을 글자로 두는 이유가 사라진다.

## 2. 규격 (여기부터 정본)

### 2-1. 인코딩

| 항목 | 값 | 이유 |
|---|---|---|
| 문자 인코딩 | **UTF-8 고정** · BOM 없음 | 리눅스·맥·윈도 공통 |
| 줄바꿈 | **LF(`\n`)** 고정 | CRLF 가 섞이면 tsv 파싱이 깨진다 |
| 한글 정규화 | **NFC** | ★맥 백업이 있다(229 크론) — 맥은 NFD 라 파일명이 갈라진다 |
| JSON | **`ensure_ascii=False`** | 한글을 한글로 저장 |
| 파이썬 파일 열기 | **`encoding="utf-8"` 명시** | 기본값은 기기마다 다르다 |

### 2-2. 파일명

- **ASCII 소문자 + 숫자 + 밑줄만.** 한글·공백·특수문자 금지
- 이유: rsync·scp·셸 스크립트·원격 기기에서 깨진다. 오늘 로그 62개가 한글 이름이다
- 사람이 읽을 이름은 **파일 안(제목 줄)** 에 쓴다

### 2-3. 시각

- **ISO 8601 + 타임존**: `2026-08-13T09:00:00+09:00`
- 이유: 기기가 6대라 로컬 시간만 적으면 순서가 섞인다

### 2-4. 기록 원본 (jsonl)

- 한 줄에 기록 하나. **첫 줄에 머리글 한 줄**(`{"schema_version": 1, ...}`)
- 필수 필드(08-05 규격 유지): `obs·action·logits·reward·done·next_obs·won·ep_id`
- 메타(조건 지문): `schema_version·env·core_hash·policy_kind·seed·결정규칙·개입`
- ★**`schema_version` 이 없으면 나중에 못 읽는다.** 없는 파일은 `v0` 으로 취급

### 2-5. 이진 캐시

- 원본에서 **언제든 다시 만든다.** 지워도 된다(카메라 RAW→JPEG 관계)
- 캐시 파일 옆에 **어느 원본에서 만들었는지**(파일명·크기·수정시각)를 적어 둔다
- 원본이 바뀌면 캐시는 **자동으로 무효** — 그 표시로 판단한다

## 3. 변환기 (사용자 요청)

기록 하나를 **여러 형식으로 내보낸다.** 만드는 것은 도구 하나다.

| 출력 | 쓰임 |
|---|---|
| `json` | 다른 프로그램에 넘길 때 |
| `md` | 사람이 읽는 보고서 (대장·문서에 붙임) |
| `tsv/csv` | 표 계산·엑셀 |
| `npz`(이진) | 분석 캐시 |

★출력은 **원본을 안 바꾼다.** 항상 새 파일로 낸다.

## 4. 적용 방침 (한 번에 다 고치지 않는다)

| 대상 | 언제 |
|---|---|
| **새로 쓰는 코드** | **지금부터 무조건** — 위 규격대로 |
| 기록·로그를 쓰는 곳 | 손볼 때 같이 고친다 |
| 기존 480곳/175곳 | ★**일괄 수정하지 않는다** — 잘 돌아가는 것을 건드리는 위험이 더 크다(규약 §7) |
| 한글 파일명 62개 | 새 로그부터 ASCII. 옛것은 그대로 둔다 |

★검사 방법: 새 파일이 규격을 지켰는지 보는 **검측 규칙 3개**를 `autobot_pattern_check.py` 에 추가한다
  (`ensure_ascii` 누락 · `encoding=` 누락 · 파일명 한글). 규약대로 **도구에 박아야** 지켜진다.

## 5. 정해야 할 것

| # | 물음 | 팀장 의견 |
|---|---|---|
| ① | 시각에 타임존을 넣나 | **넣는다**(기기 6대라 순서가 섞인다) |
| ② | 기존 480곳을 고치나 | **안 고친다.** 새것부터 + 검측 규칙으로 막는다 |
| ③ | 변환기를 언제 만드나 | 기록 형식이 굳은 **뒤에**. 지금 만들면 두 번 만든다 |
